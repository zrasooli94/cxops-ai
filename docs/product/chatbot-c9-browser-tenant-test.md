# CXOps AI — C9 real-browser staff authorization regression

**21 October 2026. SOURCE ONLY · DRAFT · RELEASE HOLD.**

## What C9 actually tests

C8 integrated the offline C6/C7 claim-review process into the authenticated
CXOps staff interface at /evaluations/claim-review and passed **834 unit/
contract tests**. It did not exercise real DOM navigation, browser file
downloads, a browser's tenant-switching cookie, or the live Next server.

C9 closes the **browser/route execution** part of that gap while still
using **fictional accounts**, a **local in-memory fake backend**, a **genuine
Next.js production build** and **genuine headless Chrome**. This is NOT
real-account authorization testing, a real FastAPI security certification,
or a human/assistive-technology usability trial.

## Test architecture and hard safety boundaries

- \`frontend/e2e/c9-local-authorization.mjs\` is a **TEST-ONLY** HTTP server
  bound to **127.0.0.1:18767**. It knows exactly two fictional organizations,
  fake JWT-shaped tokens, and a few hardcoded synthetic staff profiles:
  manager in A, manager in both, read-only, manage-only, revoked during
  request handling, and without the selected tenant membership. It accepts
  GET requests only; no database, company account, email, identity provider,
  Zendesk, OpenAI, paid SDK or external network.
- The server never validates real Nhost/JWKS tokens and **MUST NEVER** be
  deployed or treated as a replacement for production authentication. Its
  signatures are explicitly fictional, fixed and intended only for
  reproducible CI browser tests.
- \`BACKEND_API_URL\` is pinned to the above loopback service. Next.js runs
  the **actual application source** compiled with \`npm run build\` and
  served at **127.0.0.1:18768** inside GitHub Actions. No alternate
  permission bypass, special application dev mode, debug login endpoint, or
  production authentication change is added.
- \`frontend/e2e/c9-browser.mjs\` uses a pinned, **ephemeral**
  \`playwright-core\` browser test driver and the runner's installed
  Google Chrome in headless mode. The existing package.json and npm
  lockfile are not changed. Browser requests to outside loopback are
  explicitly aborted; service workers are disabled.
- No runner environment contains live provider keys, actual session
  tokens, a production DB URL or feature activation. The CI workflow
  checks these conditions before starting Next. It uses a read-only token
  and deliberately does not call Vercel, Render or any real CXOps
  account/backend.
- All test CSV content is **genuinely generated by C6 Python** from the
  committed *fictional* 11-case/12-claim dataset. Source SHA-256 authenticity
  stays with C6 Python; the browser demonstrates the UI's actual import/edit/
  download behavior but does not certify independently reviewed accuracy.

## Browser acceptance cases

| Scenario | Expected browser/server behavior |
| --- | --- |
| Missing session cookie | Actual protected Next page redirects to /login before rendering reviewer content |
| Staff has evaluation.read only | Route is denied; file import and claim editor are absent |
| Staff has evaluation.manage only | Parent evaluation.read guard + server double-check deny |
| Authorization grant revoked after the first successful request | New full SSR request denies staff review and no previous claim is visible; a second `getMyAuthorizationReadOnly` within the *same render* may reuse the first GET response, so it is **not** certified as an independent mid-request revocation check |
| Manager of Org A selects Org B where read-only | Route denied; Org A's privilege cannot unlock B |
| Tenant not in logged-in subject's memberships | Redirect to existing tenant-selection handler, no reviewer |
| Valid manager in Org A | Actual Next page visible; import C6 CSV; label a fictional claim, quote cited source, see progress, download private **draft** CSV |
| Manager in both organizations switches A → B | Real cookie + Next SSR request refresh; Org A's in-memory review is absent in B even with manage rights |
| API audit | Only expected GET /me/organizations or /me/authorization are observed in the fake service; no production writes or unauthorized provider requests |

Two **fictional only** screenshots are uploaded to the successful GitHub
Actions run for product inspection (desktop after editing, mobile on an
empty Org B review). They contain no real customer or reviewer data.
Screenshots are NOT proof of VoiceOver/TalkBack or Safari behavior.

## What remains unverified

1. **Real backend identity**: Test tokens are fictional. This does not
   certify Nhost issuer validation, session expiration/refresh,
   production JWT signatures, actual tenant DB memberships or revocation
   in a real environment. Owner-approved disposable credentials and a
   dedicated isolated staging environment are needed before real-account
   tests; no such permissions were assumed in C9.
2. **Org switch through complete UI**: The test changes a browser's trusted
   tenant-selection cookie and reloads the actual Next server route. It
   doesn't call the real OrganizationSwitcher mutation, because that
   entails refreshing genuine Nhost sessions and backend tenant state.
3. **Browser coverage**: Google Chrome (Linux headless) exercises DOM
   and file download. Safari on macOS/iPhone, Android Chrome with virtual
   keyboard, VoiceOver and TalkBack still require human/device review.
4. **Reviewer independence**: Self-attested A/B names are not independently
   authenticated, and no private per-tenant reviewer assignment, durable
   source snapshot or audited adjudication database exists. Offline
   C6 Python still verifies canonical synthetic file fingerprints.
5. **Model factuality**: C5 lexical contradiction checking, C6/C7/C8
   human-review tooling and C9 browser testing do not establish real
   model-grounded answer accuracy, multilingual faithfulness or
   general entailment. Real-model evaluation and provider spend require
   separate owner authorization.
