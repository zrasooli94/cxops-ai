# CXOps chatbot C2 — synthetic FAQ quality and release evidence

**Scope:** source-only chatbot product work. **Not a live-model evaluation or
permission to enable customer-facing autonomous decisions.** All businesses,
tenant IDs, questions, documents and model outputs in this suite are fictional.

## Customer-facing changes

1. **Write for the visitor, not the employee:** the knowledge-answer model
   is now told to speak directly to the customer, use the customer's language
   when possible, and avoid implying it has booked, refunded, contacted staff
   or made an external change. Multi-part questions should separate sourced
   facts from unknown information. Business-specific rules are still only
   sourced from the tenant's retrieved knowledge.
2. **Refuse structurally unusable evidence:** the public answer gate verifies
   a positive integer retrieval count, nonempty unique canonical S1/S2/etc.
   source references, valid numeric finite best similarity inside 0..1 and
   at/above the configured minimum, nonempty non-fallback answer, and citation
   membership. The existing opt-in, pure-information intent, action=respond,
   no business tool, human approval and tenant controls remain unchanged.
3. **Build a repeatable product-quality dataset:** a fictional bicycle
   workshop and a different fictional print studio hold isolated knowledge,
   including operational service FAQs, warranty, appointment confirmation,
   weekly hours, Persian content, explicit non-guarantees, low-relevance
   retrieval and intentionally contradictory policies.

## Scripted offline acceptance matrix

The fixture lives at
\`tests/fixtures/chatbot_c2_synthetic_faq.json\`. The test executes the
**actual** \`RAGService.answer\`, source filtering and citation repair,
followed by the **actual** customer-facing
\`PublicChatService._grounded_auto_reply_or_none\`. It stubs only model,
retrieval, and observability boundaries; the model reply text is
*preauthored*, not generated by OpenAI. Outbound HTTP/socket attempts fail.

| Scenario group | Cases | Required offline behavior |
| --- | --- | --- |
| Routine product/service FAQs | Bike service, workmanship warranty, bookings, Sunday hours; print studio hours, defect refund policy | Source-backed answer is published; customer gets natural text without internal \`[S1]\` markers; **no action is executed** |
| Language behavior | Persian bicycle-repair FAQ | Scripted answer remains in Persian; actual RAG system prompt explicitly instructs same-language customer response |
| Missing / inappropriate knowledge | Price unknown, bicycle repair asked of print studio, irrelevant airline question | No grounded public answer; absence or low similarity prevents a paid model call in these stubs |
| One bounded citation repair | First response lacks citation, repaired response has \`[S1]\` | At most two fake model calls; publish only when citation passes |
| Citation recovery failure | Both generated mocks cite unknown \`[S99]\` | Do not auto-publish; handoff required |
| Knowledge conflict | Current 30-day vs older 14-day warranty | Scripted response identifies conflicting records and cites both; *not* evidence the real model detects contradictions |
| Retrieved prompt injection | Retrieved workshop note contains an instruction to reveal passwords | The **scripted fake model** ignores the untrusted instruction and answers the legitimate service fact. Real prompt-injection resistance is **not certified** |
| Customer authorizations | Disabled flag, missing agent, action/mixed intent, human review, business tool | The existing \`_grounded_skip_reason\` refuses auto-publication |
| Malformed evidence | NaN/Inf/negative/over-one/string similarity, low similarity, Boolean count, duplicate/unknown IDs, missing answer/citation | Deterministic public eligibility rejects the result |

**Metadata alone never proves truth.** A deliberate negative demonstration
\`test_citation_marker_cannot_prove_semantic_truth\` constructs:

- Fictional cited note: **“Aster bicycle repairs are not free.”**
- Invented LLM answer: **“All Aster bicycle repairs are free. [S1]”**

The current citation service (and this C2 metadata gate) still accepts
\`[S1]\` because syntactic citation presence is not an entailment check.
**That passing adversarial test records an unresolved quality gap** rather
than hiding it behind a green test count. No claim of factual correctness,
semantic faithfulness, hallucination elimination or model robustness should
be derived from this scripted suite.

## Real public API regression, but still offline

The isolated CI lane includes \`tests/test_public_chat.py\` against its own
exact disposable loopback PostgreSQL 16 service, a guarded development
environment and mocked AI/knowledge responses. It exercises the real public
session API, tenant checks, published/handoff response routing, answer
gating, message dedupe and follow-up handoff behavior; it does **not** contact
OpenAI or business providers. The strict
\`scripts/chatbot_c2_disposable_guard.py\` refuses non-GitHub CI, unapproved
database host/name/port, real provider keys or enabled external dispatch.

## Product next steps

**C2 next (needs separate source-only draft):** a bounded, testable
semantic-evidence verifier and human-reviewed FAQ evaluation with real model
outputs, after explicit permission for any paid provider calls. Evaluate
support of *each* claim by a cited passage (including negative statements)
and require an explicit abstention when no support exists. Do not treat an LLM
self-grader as mathematical proof. Preserve all source/tenant boundaries.

**C3:** multi-turn follow-up context and mobile UI polish with browser tests,
clear knowledge provenance visible only when tenant-approved for customers,
and honest AI-vs-human handoff copy. Current RAG public call receives the
latest question, so follow-up references such as "What about weekends?" are
not certified as context-aware.

**Commercial:** owner-managed knowledge ingestion, source versioning,
tenant-level quality dashboards, controlled per-tenant opt-in, cost caps, and
separate provider action approvals. Avoid inventing company facts in system
prompts; the knowledge corpus stays the source of truth.

## Safety and release boundaries

independent from Render worker PRs #44–#49. No production deployment, branch
merge, provider credential/paid call, Render scheduling, activation of Phase
